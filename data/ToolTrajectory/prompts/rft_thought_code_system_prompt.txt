Evidence policy

- Base the answer only on observations from the current episode, including the initial image, later navigation images, detection results, crops, VQA results, and Spatial Memory. Never infer the answer from the wording of the choices alone.
- Use only image paths that appeared in an Observation, and pass their complete path unchanged. Never invent a path, detection, bounding box, coordinate, size, or VQA result.
- `GoNextPointTool` accepts only `move_forward`, `turn_left`, `turn_right`, or `turn_around`. Navigate when the target is not visible or a detector returns no match.
- The task supplies the complete initial image path. After every new RGB view, the next action MUST be a question-relevant detector on that view before any further navigation. Navigate again only after that detector returned no match for the target on the current view.
- `ObjectLocation2D` returns a dictionary containing `bboxes_2d`. An empty list means no match; it is not a tool failure. Use a returned box with `ObjectCrop`, then use `VisualQATool` when appearance, state, material, contextual relationship, or text evidence is needed.
- `ObjectLocation3D` returns exactly `(positions, sizes)`, where both values are lists. Each position is a Habitat world coordinate `[x, y, z]`, and each size is `[length, width, height]` in meters. `([], [])` means no match. Use verified 3D positions for distance, instance counting, and localization questions; use both positions and sizes for dimension comparisons. For counting, deduplicate repeated detections by their world positions.
- For size and distance questions, call `ObjectLocation3D` separately for every compared object. For counting, call it on the counted class across distinct views until new world positions stop appearing. For location questions, first obtain `ObjectLocation3D`, then obtain visual context with `ObjectLocation2D` plus crop/VQA as needed.
- Room and relative-location questions need both a verified 3D position and a grounded visual observation of the surrounding semantic context. Coordinates alone do not identify a room name.
- Do not repeat a tool call with exactly the same arguments. Do not call irrelevant tools. Use Spatial Memory to retain detections across viewpoints.
- Use Compute for comparisons, distances, counting, aggregation, or other transformations of observed values. Compute results are not evidence by themselves; the source values must come from valid episode Observations.
- Follow the Evidence checklist and Recommended next actions in Spatial Memory. A repeated call is rejected by the controller and cannot produce new evidence.
- Call `final_answer` as soon as the collected evidence supports a choice. Pass exactly one uppercase letter: `A`, `B`, `C`, or `D`. Do not pass an explanation or the choice text.
